# Аптека рядом — frontend-портфолио

[Открыть опубликованное демо](https://shavelmaxim.github.io/prototype-farmeconom/) · [Успешный deployment](https://github.com/ShavelMaxim/prototype-farmeconom/actions/runs/42349471470)

Независимый учебный концепт аптечного магазина для собеседования в Фармэконом. Данные вымышленные; реальные заказы не создаются. Next.js App Router экспортируется в статические файлы для GitHub Pages.

## Возможности

44 демонстрационных товара, поиск с debounce, фильтры и сортировка в URL, прямые страницы товаров, три аптеки с разными ценами и наличием, сохраняемая корзина, демо-оформление. Избранное с отменой удаления, история последних30демо-оформлений со снимками цен и повтором после проверки остатков. Настройки текста100–200%, контрастные схемы, интервалы и reduced motion. Мобильная нижняя навигация, закреплённая покупка на странице товара, фильтры в Drawer с черновиком и ползунком цены. Выдача порциями по12с фокусом на первом новом товаре; поиск и фильтры охватывают все44позиции. На телефоне скрытая desktop-панель не монтируется; desktop-фильтры загружаются по media query.

Подбор: категория, цена/наличие выбранной аптеки, аудитория, точный возраст ребёнка, особенности, бренд/производитель, упаковка, форма, дозировка/вещество учебного образца, вкус/масса/объём, материал/размер и тип кожи. Зависимые фильтры показываются при наличии данных, выбранные значения видны метками. «Для кормящих» и «Для беременных» в демо относятся к принадлежностям материнства; медицинской пригодности не обещают. Вымышленные лекарства/гомеопатия явно помечены, реальных инструкций и рекомендаций нет.

## Стек и архитектура

Next.js, TypeScript strict, React, Ant Design/CSS Modules, Redux Toolkit/RTK Query, React Hook Form/Zod, Vitest/Testing Library, Playwright. Версии закреплены в package-lock.json. Node.js 24.

Облегчённая FSD: app (маршруты) → src/widgets → src/features → src/entities → src/shared; src/app собирает провайдеры. Redux хранит корзину, аптеку и локальные пользовательские данные, RTK Query — результаты адаптеров, URL — применённые фильтры, локальный state — черновик Drawer, RHF — форму оформления. Стабильный serverState Provider обеспечивает восстановление при hydration. В localStorage сохраняются только валидированные данные, без персональных полей; при недоступности storage показывается ограничение текущим сеансом.

AntdBoundary с Registry/ConfigProvider/русской темой расположен у экранов товара, корзины, оформления и динамических диалогов. Простые элементы главной — семантический HTML/CSS Modules. Общий useCatalogCart управляет количеством и действиями сетки; fieldset блокирует добавление до восстановления корзины. Это сохраняет Ant Design в стеке и сокращает начальный клиентский граф.

HTML и карточки создаются во время сборки. Фильтрация, наличие и демо-оформление выполняются в браузере. Это не серверная защита цены или заказа. Деньги — целые копейки. Данные не сохраняются на сервере, персональные поля отсутствуют.

## Запуск

```powershell
npm ci
npm run dev
```

Для воспроизведения GitHub Pages:

```powershell
$env:NEXT_PUBLIC_BASE_PATH='/prototype-farmeconom'
npm run build
npm start
```

Статический просмотр: http://127.0.0.1:3100/prototype-farmeconom/. Для размещения в корне уберите NEXT_PUBLIC_BASE_PATH перед сборкой и запуском. После смены пути нужна пересборка. npm start раздаёт out; сервер Next.js на Pages не запускается.

## Данные и будущий PHP API

По умолчанию RTK Query использует локальные адаптеры с задержкой и моделированием ошибок. NEXT_PUBLIC_API_URL с завершающим / включает HTTP-режим: GET products возвращает полный каталог с предложениями всех аптек; поиск и фильтры вычисляются из общей проверенной выборки на клиенте, POST demo-checkout с pharmacy/pickup/acknowledge/items. Zod проверяет успешные ответы. Карточка, корзина и оформление используют общий RTK Query-кеш getInventory, в HTTP-режиме статические цены не подставляются при сбое. Форматы моделей описаны в src/entities/product/model.ts и src/features/checkout/model.ts. PHP/MySQL пока не реализованы; HTTP-режим не проверен с настоящим backend. NEXT_PUBLIC_* доступны браузеру и не должны содержать секреты.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
npm run check:deployment -- https://shavelmaxim.github.io/prototype-farmeconom/
```

E2E проверяют out на статическом сервере, включая базовый путь, mobile, корзину, URL, ошибки и прямой вход в карточку. Локально нужен Chrome; Pages CI использует Chrome из образа ubuntu-24.04 и проверяет его наличие. PLAYWRIGHT_CHANNEL позволяет явно выбрать установленный браузер; без него обычный CI сохраняет стандартный Chromium. PLAYWRIGHT_BASE_URL позволяет проверить опубликованный URL без локального сервера. Mobile — эмуляция в Chromium/Chrome, не Safari.
