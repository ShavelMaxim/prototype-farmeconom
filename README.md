# Аптека рядом

Независимый frontend-концепт аптечного интернет-магазина для портфолио. Не официальный сайт Фармэконом. Товары, упаковки, бренды, адреса и остатки вымышлены; реальная покупка не выполняется.

## Быстрый старт

Node.js 24 рекомендуется (проект проверяется на 24.21.0), npm. Из корня проекта:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Для production:

```sh
npm run build
npm start
```

## Что реализовано

- 24 товара и три демонстрационные аптеки с разными ценами и остатками.
- Серверное начальное содержимое каталога; предварительная генерация карточек товаров.
- Поиск с debounce 300 мс; категория, сортировка и наличие в URL.
- RTK Query: загрузка, кеширование, повтор запроса. При обновлении остаётся предыдущая выдача; добавление по устаревшим данным заблокировано.
- Мобильные фильтры в Drawer, выбор аптеки в Modal.
- Корзина с ограничением количества, пересчётом при смене аптеки и восстановлением localStorage после hydration.
- Форма демо-оформления с RHF/Zod. Сервер проверяет остатки и сумму по своим данным. Никакие контактные данные не нужны.
- Панель проверки задержки и ошибки внизу каталога, локальные ошибки, пустые состояния, route-level скелетон.
- Русский интерфейс, видимый фокус, skip-link, reduced-motion, собственные CSS-иллюстрации упаковок.

## Стек

Next.js 16.4.5, React 19.3.1, TypeScript 6.0.3, Ant Design 6.7.0 + Next.js Registry, CSS Modules, Redux Toolkit/RTK Query, React Hook Form/Zod, Vitest/Testing Library, Playwright, ESLint. Точные версии закреплены в package.json и package-lock.json.

Vite не используется для сборки приложения; он является внутренней зависимостью Vitest. PHP и MySQL отложены до настоящего backend-этапа.

## Архитектура

```text
app/                    тонкие маршруты Next.js, metadata и Route Handlers
src/app/                композиция Redux, Ant Design, восстановление состояния
src/widgets/            каталог, шапка, карточка, корзина, оформление
src/features/           действия корзины, выбор аптеки, оформление
src/entities/           модели товара и корзины, repository, продуктовый API
src/shared/             API base, конфигурация, типизированные hooks, тестовый setup
tests/e2e/              пользовательские сценарии в desktop/mobile
```

Это облегчённая FSD. Runtime-зависимости идут сверху вниз. Исключение для type-only зависимости типизированных Redux hooks от типов store описано в AGENTS.md. На этом масштабе нет дополнительных barrel-файлов и абстрактных фабрик компонентов.

Redux хранит клиентскую корзину и аптеку. RTK Query хранит результаты HTTP-запросов. URL хранит применённые фильтры. RHF хранит состояние формы. Локальное React-состояние хранит открытые панели и поисковый черновик. Store создаётся на экземпляр Provider, не делится между серверными запросами.

## API

`GET /api/products?q=&category=Все товары&sort=popular&available=false&pharmacy=central`

- `sort`: popular / price-asc / price-desc / name.
- `pharmacy`: central / park / family.
- `demo=slow` добавляет задержку 1,5 секунды; `demo=error` возвращает 503. Это намеренные ограниченные возможности тестового API, не production-настройки.
- Невалидные параметры → 400. Цены представлены целыми копейками.

`POST /api/demo-checkout`

```json
{
  "pharmacy": "central",
  "pickup": "today",
  "acknowledge": true,
  "items": [{ "id": "product-2", "quantity": 1 }]
}
```

API проверяет Zod-контракт, существование товаров и остатки; сам вычисляет сумму. 400 — неправильный запрос; 409 — недоступный товар/количество; 200 — временный номер демонстрации. Номер не сохраняется, товар не резервируется. Повторные запросы безопасны для демо, но production потребует идемпотентности, транзакций и серверной корзины.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

E2E запускаются на production-сборке на 127.0.0.1:3100 и используют установленный Chrome. Перед ними нужен `npm run build`; dev-сервер на 3000 может оставаться открытым. В CI базовые проверки заданы в `.github/workflows/checks.yml`; браузерные тесты пока запускаются отдельно и требуют Chrome.

Актуальные фактические результаты, этапы и ограничения — в PLAN.md и CONTEXT.md. Нельзя считать тест пройденным только по наличию тестового файла.

## Публикация

Выбран Vercel; конфигурация и проверки подготовлены. Инструкция и актуальный статус — [DEPLOYMENT.md](DEPLOYMENT.md). Внешняя публикация ожидает подключения аккаунта владельца. `npm run check:deployment -- <URL>` проверяет страницы и демо-API; `PLAYWRIGHT_BASE_URL` позволяет выполнить E2E на опубликованном адресе.

Нужен хостинг с поддержкой настоящего Next.js/Node и Route Handlers: сборка `npm ci && npm run build`, запуск `npm start` (для внешнего Node-хоста задайте адрес прослушивания и порт в его launch command). `output: export` не подходит: приложение использует динамический каталог и POST API. Секреты и база данных для этой версии не нужны. На старте внешнее развёртывание не настроено; локальная ссылка не является публичным хостингом.

## Границы и следующие шаги

Нет реальных лекарственных данных, советов по лечению, аккаунтов, оплаты, доставки, административной панели или актуальной интеграции с аптеками. `robots: noindex` предотвращает намеренную индексацию учебных карточек, но не является ограничением доступа.

Для production отдельно нужны backend PHP/MySQL или другой согласованный API, контроль цены/остатка на транзакции, авторизация, мониторинг, требования к персональным данным и полный аудит доступности/производительности. Текущий проект не заявляет соответствия WCAG и не обещает рост конверсии без измерений.
