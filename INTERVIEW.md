# Демонстрация на собеседовании — 5–7 минут

## 1. Задача — 30 секунд

«Я сделал самостоятельный frontend-концепт аптечного магазина. В центре — поиск товара, выбор точки получения и понятное поведение при загрузках и ошибках. Это учебные данные; я не утверждаю, что знаю внутреннюю архитектуру Фармэконом».

## 2. Каталог — 1 минута

Открыть главную. Найти «термометр», выбрать сортировку. Показать параметры URL и возможность открыть эту ссылку отдельно. На узком экране открыть фильтры. Объяснить разделение UI: готовые элементы Ant Design и собственная компоновка с CSS Modules.

## 3. Устойчивость — 1 минута

Внизу каталога включить медленную сеть, изменить запрос. Старые карточки сохраняются; статус показывает обновление. Переключить на ошибку, показать локальное сообщение и повтор. Вернуть обычную сеть. Не обещать, что скелетон нужен при каждом действии: при повторной загрузке сохранённые данные полезнее.

## 4. Корзина и остатки — 1–2 минуты

Добавить гель для бережного очищения в Центральной аптеке. Открыть корзину, обновить страницу. Выбрать «У парка»: геля там нет, оформление блокируется с объяснением. Вернуть Центральную. Объяснить: локальная корзина ускоряет интерфейс, в демо проверка выполняется в браузере; для настоящего магазина её обязательно повторяет сервер.

## 5. Оформление — 1 минута

Попробовать продолжить без подтверждения учебного режима: показать ошибку поля. Подтвердить, завершить демо. Уточнить, что персональные данные не собираются, реальные заказы не создаются.

## 6. Код и компромиссы — 1–2 минуты

- Next.js: HTML каталога формируется при сборке, карточки генерируются заранее; интерактивность — клиентские компоненты.
- RTK Query не дублируется отдельным fetch-кешем. Redux — только общее клиентское состояние.
- Фильтры в URL, форма в RHF, схемы Zod в форме и демонстрационном адаптере.
- Деньги в копейках; отдельные тесты на смену аптеки и неподходящие остатки.
- Моковый repository можно заменить PHP API; HTTP-режим включается через NEXT_PUBLIC_API_URL; PHP API пока не реализован.
- Дальше: реальные интеграции, наблюдаемость, транзакционное резервирование и измерения производительности.

## Что не заявлять

Не говорить «полностью переделал Фармэконом», «сайт безопасен», «конверсия выросла», «все пользователи предпочитают этот вариант». Корректно: «предложил концепт», «проверил перечисленные сценарии», «эту гипотезу проверил бы на пользователях».
