# Синхронизация категорий — 9 ноября 2026

На опубликованном42f0d75 воспроизведён дефект: переход по верхней плитке меняет category в URL, но заголовок, выдача и выбранный боковой фильтр остаются прежними. Прямой вход в «Для детей» после загрузки даёт6товаров; переход плиткой в «Медтехника» оставляет эти6, хотя адрес уже другой. Боковая кнопка «Уход и гигиена» корректно обновляет выдачу до10. Ошибок JavaScript нет. Это разные пути управления состоянием, а не подтверждённая особенность браузера или Codex.

Причина: useCatalogSearch использует useSyncExternalStore и слушает popstate и catalog-url-change. Нативные фильтры отправляют собственное событие; навигация Next Link не отправляет ни его, ни popstate. Быстрые ссылки появились при редизайне. Прежний E2E категории проверял боковые кнопки/Drawer, не плитки и не сброс категории ссылкой «Каталог».

Добавлен CatalogUrlObserver: штатный useSearchParams следит за навигацией Next.js и уведомляет существующую подписку каталога. Изолирован в пустом Suspense, возвращает null; весь остальной каталог и Server Component CatalogIntro остаются в статическом HTML. History API не переопределяется, поведение ссылок/модификаторов не меняется. Нативные фильтры продолжают использовать свой немедленный сигнал, повторное уведомление не меняет snapshot и не создаёт запись History.

Новые регрессии:

- Прямой вход по ссылке пользователя, сброс через «Каталог», Back/Forward на desktop/mobile.
- Плитки «Медтехника» → «Уход и гигиена» → «Для детей» с главной и прямой ссылки; URL, заголовок, количество и выбранная категория согласованы. Back/Forward/reload. Проверяется широкий layout в профилях мыши и touch.
