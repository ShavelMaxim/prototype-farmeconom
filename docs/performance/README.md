# Измерения производительности

Эта страница сохраняет ранние одиночные замеры. Актуальная итерация с CPU-профилями, контрольными сериями и результатами исправлений: [PROFILING.md](PROFILING.md).

Lighthouse запускается локальным Chrome для опубликованного GitHub Pages URL, с мобильным профилем и стандартным simulated throttling. Сохраняется JSON без ручного изменения чисел.

Исходный одиночный замер: before.json — Performance 67/100, FCP 1,1 с, LCP 2,8 с, TBT 1520 мс, CLS 0, Speed Index 4,5 с.

Измеряется лабораторная производительность конкретного запуска. TBT не является полевым INP. Итоговые баллы зависят от загрузки компьютера, сети и кеша, поэтому единичное сравнение до/после не доказывает причинный эффект и не описывает всех пользователей. Для статистического вывода нужны повторные замеры в одинаковой среде и полевые данные при достаточном трафике.

Конкретные изменения: диалог аптеки выделен в отдельный динамический chunk и загружается при открытии; AddButton подписан на своё количество, аптеку и hydration вместо всей корзины; localStorage не перезаписывается на каждое действие RTK Query. Изменения данных и доступности тоже влияют на итоговую сборку, поэтому нельзя приписывать всю разницу одному lazy import.

Повторение:

```powershell
node node_modules/lighthouse/cli/index.js https://shavelmaxim.github.io/prototype-farmeconom/ --only-categories=performance --output=json --output-path=docs/performance/after.json --chrome-flags="--headless --no-sandbox" --quiet
```

Результат после публикации и ссылка на проверенный deployment дополняются в CONTEXT.md.

Промежуточный замер после выделения диалога: after-modal.json — score70, LCP2,9s, TBT1010ms, CLS0, начальный JS420406 байт против415881 байта исходно. Это не доказывает устойчивое ускорение; дополнительные схемы данных увеличили JS. Следующий эксперимент — отложенная загрузка закрытой панели фильтров; финальный замер сохраняется отдельно в after.json.

## Итоговый замер опубликованной версии f87b902

| Метрика                    | До          | После диалога | После диалога и фильтров |
| -------------------------- | ----------- | ------------- | ------------------------ |
| Performance                | 67          | 70            | 66                       |
| LCP                        | 2,8 с       | 2,9 с         | 3,0 с                    |
| TBT                        | 1520 мс     | 1010 мс       | 1410 мс                  |
| CLS                        | 0           | 0             | 0                        |
| Начальный JS, transferSize | 415881 байт | 420406 байт   | 416540 байт              |

Файлы: before.json, after-modal.json, after.json. Все значения — одиночные лабораторные прогоны, не медианы и не полевые данные.

Вывод: устойчивое ускорение не доказано; исходный результат и финальный практически сопоставимы, LCP в финальном прогоне немного выше. После добавления схем валидации и общего слоя данных начальный JS не сократился относительно исходной версии. Поэтому ни прирост скорости, ни улучшение INP не заявляются.

Основные наблюдаемые затраты последнего прогона: Script Evaluation около 2034 мс, Style & Layout около 1115 мс; разбор/компиляция JavaScript около 197 мс. Дальнейшая оптимизация требует профилирования выполнения и рендеринга крупных chunks и повторных измерений в одинаковой среде. Lazy imports сами по себе эту проблему не решили. Динамические панели и работа фокуса проверены E2E.
