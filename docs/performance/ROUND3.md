# Стартовый JavaScript и гидратация

7 ноября 2026. Контроль: исходный код da7ee12, опубликованное приложение688b589. Цель — Performance выше90 с сохранением Next.js App Router, React/TypeScript, Ant Design, Redux Toolkit/RTK Query, RHF/Zod и пользовательских сценариев.

## Причины и изменения

Первоначально AntD находился в root Providers/layout и даже в root error boundary. Поэтому общий рантайм библиотеки, темы, CSS-in-JS и регистрация SSR-стилей загружались на главной. В каталоге дополнительно гидратировались24полноценных AntD Button, два Select и отдельные Redux-подписки кнопок.

Изменения:

- AntdBoundary объединяет AntdRegistry, ConfigProvider, русскую локаль и прежнюю тему. Он расположен у потребителей: товар, корзина, оформление и их loading states; динамические PharmacyDialog/FilterDrawer. Root Redux Provider сохраняет стабильный serverState и восстановление корзины. Глобальные AntD-импорты удалены из главной, шапки и error boundary.
- Простые элементы главной используют семантические button/input/select/checkbox и общие CSS Modules. AntD продолжает обслуживать диалоги, Drawer и компоненты остальных экранов. Размеры, доступные имена, фокус, disabled, подписи и поведение URL сохранены. Нативный select обслуживает короткие фиксированные списки; поиск по списку и виртуализация там не требовались.
- useCatalogCart даёт сетке одну Redux-подписку и карту количеств. ProductCard memo получает числовое quantity. Добавление делегируется на контейнер, товары определяются по исходной карте products, а не по цене/остатку из DOM. Проверяются готовность, busy и текущий остаток. Сетка блокируется native fieldset до восстановления корзины. На странице товара AddButton использует то же представление CartAction.
- Единый live region сообщает об изменении корзины. Сохраняются ограничения количества, восстановление, отмена выбора аптеки, HTTP-валидация Zod и блокировка устаревших цен. Схемы и проверки не отключались ради оценки.
- Первый поиск/сортировка заблокированы до подключения обработчиков. Нет задержки по таймеру, idle-гейта гидратации или скрытия готового HTML:24карточки доступны без JS. Динамические диалоги предзагружаются по наведению/фокусу; видимый LoadingNotice сообщает о загрузке, не меняя геометрию шапки.
- Бюджет cold-start JS <750000 несжатых байт защищён E2E до открытия диалогов. После открытия диалога загрузка AntD ожидаема и не входит в этот бюджет.

`cold-graph.json` анализирует source maps фактически загруженных скриптов. После изменений в них отсутствуют antd, @ant-design/cssinjs и @ant-design/nextjs-registry. Все карты найдены. Это проверка начального графа, а не удаление AntD из проекта.

## Отклонённые эксперименты

- Штатный Webpack на том же исходном коде: локальная медиана74 против73 в исходной серии; JS уменьшился лишь примерно на0,5%. Сборка стала дольше, убедительного выигрыша нет. Оставлен Turbopack, новые зависимости не добавлялись.
- Только облегчение кнопок/Select до переноса провайдера: JS около985KB, медиана73. Этого было недостаточно. Raw `before-*`, `webpack-*`, `native-*` — исследовательские серии; итоговая контрольная пара — `control-*`/`after-*`.
- Отвергнутые ранее глобальный static CSS/zeroRuntime и отключение проверок не возвращались.

## Воспроизведение

```powershell
$env:PROFILE_BUILD='true'
$env:NEXT_PUBLIC_BASE_PATH='/prototype-farmeconom'
npm run build
npm start
```

В отдельном терминале: `node scripts/profile-page.mjs label out URL`, `node scripts/coverage-page.mjs label URL`, `node scripts/probe-interaction.mjs label URL`. Lighthouse — три последовательных запуска с `--only-categories=performance --output=json --chrome-flags="--headless --no-sandbox"`. Не выполнять build/тесты параллельно измерениям. Для обычной production-сборки убрать PROFILE_BUILD.

Подходы: [Next.js о расположении context providers](https://nextjs.org/docs/app/getting-started/server-and-client-components#context-providers), [lazy loading](https://nextjs.org/docs/app/guides/lazy-loading), [штатный Webpack](https://nextjs.org/docs/pages/api-reference/turbopack#using-webpack-instead). Использованы и локальные docs установленного Next16.4.
